# PGT-mt Atlas — публикация на отдельном домене

Единственный источник кода и научных данных — [fresll/pgt-mt-atlas](https://github.com/fresll/pgt-mt-atlas). Этот репозиторий содержит только конфигурацию сборки и проверок; он не меняет исходный Atlas, его GitHub Pages или старые ссылки. Публикация нового домена остаётся в существующем GitHub Pages и не меняет DNS, custom domain или HTTPS.

## Автоматическая синхронизация — пока не включена

Расписание в `.github/workflows/atlas.yml` закомментировано. После отдельного одобрения владельца включите две строки `schedule` и `cron` и внесите их в `main` этого репозитория. GitHub запускает расписание из default branch приблизительно каждые 30 минут; запуск может задержаться. Не нужны PAT или другие секреты: используются публичные GitHub API и штатный `GITHUB_TOKEN`. У репозитория должны быть разрешены Actions и доступ к публичному исходному репозиторию. Включение расписания может автоматически опубликовать версию при первом запуске, если SHA различаются.

Сначала выберите наиболее позднее развёртывание источника в environment `github-pages`, проверьте успешный статус и адрес старого сайта. Его status связывается с завершившимся успешно workflow `.github/workflows/deploy-pages.yml` из `main`, а SHA развёртывания и workflow должны совпадать. Новые коммиты без успешной публикации не выбираются. Неоднозначные или недоступные данные о публикации вызывают ошибку без deploy. Из публичного `atlas-provenance.json` нового сайта берётся SHA; совпадение означает пропуск сборки и публикации. Иначе проверяется и собирается точно выбранный SHA. Перед deploy проверка повторяется: если исходный сайт уже обновился или целевой домен уже содержит SHA, deploy отменяется. Запуски сериализованы общей concurrency-группой, включая ручные выпуски. Два независимых сайта не могут переключаться атомарно: источник может обновиться между последней проверкой и началом deploy; следующий запуск устранит расхождение после успешных проверок.

Отчёт в GitHub Actions **job summary** показывает опубликованный SHA источника, SHA нового домена, их совпадение, время последней подтверждённой автоматической синхронизации текущего артефакта (или `unknown`, если историю нельзя достоверно установить), а также причину пропуска или ошибки. После успешного deploy отдельный итог содержит SHA и время проверки опубликованных файлов. Метаданные хранятся в публичном манифесте; в нём нет секретов. При сбое до deploy текущая версия остаётся доступной. Если проверка после deploy не прошла, workflow сообщает об ошибке: автоматического отката нет.

## Проверки и происхождение

Для выбранного SHA выполняются ETL `--check`, научные golden tests, проверка сгенерированных данных, typecheck, unit-тесты, существующие браузерные, публичные и китайские сценарии. Затем собирается пять языков с `ATLAS_BASE=/` и проверяются все 110 страниц, canonical, hreflang, sitemap, robots, интерактивные графики и ссылки. Для исходного публичного браузерного набора тестовая сборка использует canonical, указанный самим набором: допускаются только адрес старого Atlas и адрес нового домена. Финальная сборка всегда использует canonical нового домена. Тесты корневого домена в `scripts/domain/` сохранены из ранее опубликованной ревизии `f6f667d57fb1c26aed021723578b3c545c827485` и исполняются против выбранного исходного кода, не заменяя его. Также проверяются счётчик и CORS.

Манифест `atlas-provenance.json` содержит SHA источника, SHA конфигурации, режим и SHA-256 всех файлов. Перед deploy отдельное задание проверяет точные байты Pages-артефакта, манифест и настроенный адрес `https://atlas.mazunin.science/`; после deploy сверяет все опубликованные файлы. Это проверка целостности в рамках запуска, а не независимая криптографическая аттестация.

## Ручной preview, выпуск и откат

В **Actions → Atlas — verified build and publication → Run workflow**:

- `preview` собирает `source.env` либо полный 40-символьный `source_sha`, если он указан. Результат `atlas-preview-noindex` предназначен для локальной проверки и не публикуется. `noindex` не защищает от доступа.
- `sync-preview` выбирает текущий успешно опубликованный источник и строит noindex preview только при отличии от нового домена. Это безопасная проверка выбора без deploy; при совпадении будет пропуск.
- `release` выпускает закреплённый `source.env` либо явно заданный полный `source_sha`. Нужны ветка `main` и точная строка `PUBLISH atlas.mazunin.science`. Используйте только ранее проверенный SHA и предварительно проверьте preview. Защита домена и все тесты остаются обязательными.

Для ручного отката сначала отключите автоматическое расписание: иначе следующий запуск восстановит текущую успешно опубликованную версию источника. Выберите ранее проверенный SHA, выполните `preview`, затем по отдельному решению владельца — `release` с этим SHA и подтверждением. После проверки возвращение расписания снова приведёт целевой домен к версии источника. Ручной выпуск и откат не меняют старый Atlas и не выполняют действий с DNS.
