# PGT-mt Atlas — независимая публикация

Это технический репозиторий, не копия научных исходников. Единственный источник — [fresll/pgt-mt-atlas](https://github.com/fresll/pgt-mt-atlas), закреплённый полным SHA в `source.env`. Текущий исходник: `f6f667d57fb1c26aed021723578b3c545c827485` (ветка подготовки, GitHub CI прошёл); его workflow прямого переключения не запускается. Старый сайт и его репозиторий этой конфигурацией не публикуются и не настраиваются.

В `.github/workflows/atlas.yml` есть **только ручной `workflow_dispatch`**. По умолчанию `preview` формирует артефакт с `ATLAS_BASE=/`, пятью языками и `noindex`; он не выполняет `deploy-pages`, не создаёт сайт и не требует включения Pages. Индексируемая корневая сборка также проверяется внутри задания, но в режиме preview не загружается как Pages-артефакт. `noindex` — указание поисковикам, не защита доступа; скачивайте и проверяйте preview локально, не публикуйте его в интернете.

## Первый тестовый запуск — после разрешения владельца

1. На GitHub в этом репозитории откройте **Actions → Atlas — verified manual build and publication → Run workflow**, ветка `main`, `mode=preview`, поле подтверждения оставьте пустым. Для этого нужны Actions и право записи; Pages, DNS и custom domain не нужны. Если Actions отключены политикой репозитория, включите их в настройках этого нового репозитория.
2. Дождитесь зелёного завершения, скачайте артефакт `atlas-preview-noindex` и распакуйте. Он удаляется GitHub по истечении срока хранения. Проверьте `atlas-provenance.json`: source SHA, SHA конфигурации, mode, base и хеши файлов. Из каталога артефакта запустите локальный статический сервер, например `python3 -m http.server 8000`, и откройте `http://localhost:8000/ru/`, затем другие языки и глубокие страницы. Preview следует открывать в корне локального сервера; для проверки без слеша и статуса 404 используйте сервер, имитирующий Pages из исходного проекта. Проверьте Plotly и загрузки. Автотесты подменяют GoatCounter, но ручной просмотр может посылать реальные посещения — при необходимости заблокируйте его в браузере.
3. Убедитесь, что все языковые HTML имеют `noindex`, sitemap отсутствует, а исходный сайт всё ещё работает. Этот запуск не публикует на GitHub Pages.

## Проверки и происхождение

Рабочий процесс проверяет SHA checkout, ETL `--check`, научные golden tests, актуальность сгенерированных данных, typecheck, unit-тесты, прежние браузерные тесты, публичные и китайские сценарии, затем 110 корневых страниц, canonical/hreflang/sitemap/robots и графики. Preview пересобирается с `ATLAS_SOFT_LAUNCH=1`, `ATLAS_PUBLIC_LAUNCH=0` и проверяется отдельно, в том числе браузером. До вычисления хешей проверяются неизменность HEAD и отслеживаемых исходников. Все файлы результата хешируются в `atlas-provenance.json`; в release отдельное задание сверяет распакованный Pages-артефакт с манифестом и хешем манифеста из build job до публикации, а после неё сверяет опубликованные байты. Версии Python, Node и Python-пакетов закреплены; npm использует lockfile исходного проекта. Теги GitHub Actions и образ runner остаются внешними зависимостями. Это проверка целостности и происхождения в рамках одного запуска, а не независимая криптографическая аттестация или обещание побайтово одинаковых сборок в разных окружениях.

## Публикация — только после отдельного разрешения

1. Проверить выбранный SHA и зелёный preview; сохранить рабочий артефакт старого сайта и параметры DNS/Pages. В настройках **только этого репозитория** выбрать GitHub Pages Source: GitHub Actions; выполнить отдельное согласованное подключение `atlas.mazunin.science`, DNS и HTTPS согласно [GitHub Docs](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site). Процесс не настраивает Pages или DNS самостоятельно. Не удалять действующую публикацию.
2. Вручную запустить тот же workflow из `main` с `mode=release` и точной строкой `PUBLISH atlas.mazunin.science`. Задание `deploy` требует Pages с уже настроенным адресом `https://atlas.mazunin.science/`, проверяет артефакт, настройки и CORS счётчика; использовать защиту GitHub environment `github-pages` и ограничение ветки при необходимости. Иной адрес приводит к отказу до публикации. Публичная сборка использует `ATLAS_BASE=/`, `ATLAS_CANONICAL_BASE=https://atlas.mazunin.science/` и 110 индексируемых страниц.
3. Проверить оба сайта и старые глубокие ссылки, URL без слеша, query/hash, изображения, CSS, JavaScript, графики, загрузки, мобильные и RTL-страницы, счётчик и CORS из реального браузера. Подтвердить sitemap, robots и canonical. Подумать об индексации двух копий: старый сайт остаётся со своим canonical и не перенаправляет на новый. Новую поисковую политику согласовать отдельно.
4. Если проверка после публикации падает, workflow сообщает об ошибке, но **не откатывает сам** уже опубликованный артефакт. Остановить распространение нового адреса, восстановить предыдущий проверенный артефакт или выполнить новый ручной выпуск с прошлым pin; при ошибке DNS восстановить ранее записанные настройки и следить за безопасностью домена. Изменение настройки домена/DNS, повторное развёртывание и откат требуют разрешения владельца. Проверить старый сайт повторно; он остаётся независимым. Кеши DNS/браузера могут задержать восстановление.

## Обновления обеих публикаций

Подготовить новый commit в основном проекте, проверить научные данные и все тесты, зафиксировать SHA и утвердить его. Для этого технического репозитория изменить `source.env` через review; ручной preview проверит именно этот SHA. До публикации сравнить SHA и контрольные суммы данных с выпуском старого сайта, который обновляется его собственным workflow только после отдельного согласования. Ни этот workflow, ни изменение pin **не обновляют старый Atlas**. Механизм двух согласованных релизов — ручная дисциплина, не автоматическая атомарная синхронизация: до её отдельной реализации возможен временный разнобой версий. Для отката нового сайта вернуть проверенный SHA в `source.env`, прогнать preview и отдельно разрешить release.
